# Ticket 03 local capability contract

Research for [ticket 03](../../.scratch/meeting-ai/issues/03-verify-fully-local-inference-and-search-capabilities.md), scoped to R7/R9/R12/R15. This contract supplements the [earlier investigation](capability-evaluation-2026-11-01.md); it does not implement downstream product adapters or change their requirements. Public evaluation-model downloads were explicitly authorized by the user. All inference used synthetic content locally. No real Meeting, user credential, private Voice Profile, hosted provider, or production library was used.

Existing app ASR weights were read in place without modification; additional weights and runtime packages live under `/private/tmp/stillmatter-meeting-ai-03-{models,runtime}`.

Environment: macOS 15.8.1 x86_64, 32 GiB RAM, 12 logical CPUs; installed llama.cpp 0.8.0 build 11960 and Pi 1.2.0. Individual reports record actual runtime settings, hashes, wall/CPU times and process high-water RSS. Runs shared the host with other probes, so throughput is an observation, not a dedicated benchmark or resource guarantee. Peak RSS values from different processes must not be added or compared as if they were the same measurement.

## Pi lifecycle, local policy and artifact ownership

The installed [Pi protocol research](pi-rpc-research.md) remains authoritative for its version. Successful prompt acknowledgement means accepted/queued/handled. A handled prompt starts no generation; `agent_end` alone is insufficient. Require `agent_settled`, a non-aborted/non-error final assistant message, and schema/provenance validation before applying generated artifacts. The disposable probe checks LF/CRLF framing, Unicode separators, cancellation, malformed/truncated output, missing acknowledgement, child failure/deadlines and total stdout/stderr bounds. It is not a shipped RPC implementation.

An initial 4,096-token configuration produced only one output token and no artifact. The installed Pi simple-options source reserves 4,096 context-safety tokens before its output clamp; declaring only 4,096 tokens exhausts that allowance. The corrected 8,192-token lane generated actual output. The [failed configuration report](capability-analysis-initial-failure-2026-11-01.json) is retained separately. This is a version-specific integration constraint: budget system instructions, supplied evidence and output tokens explicitly, disable automatic compaction for this bounded research context, and never silently summarize away Meeting evidence.

The actual unavailable loopback-provider path acknowledges then settles with provider failure and no artifact. Missing weights/endpoints must fail with setup guidance; Retry resumes outstanding work. Retain recordings and completed checkpoints. No fallback to the existing remote print-mode `PiCodexWorker` is permitted: that worker is neither a local analysis path nor the required RPC lifecycle.

Use an explicit model/provider, loopback-only server binding, local weights, app-owned Pi configuration, a minimal environment, disabled tools/MCP/extensions/context/skills/templates/session persistence, and bounded child lifetime. `--offline` disables startup operations; it is not an OS network sandbox. Locality follows the explicit endpoint/model and disabled capabilities, not an RPC flag alone. Each research prompt uses isolated context. A production adapter must validate reset/cancellation semantics if it reuses a process.

Model downloads are network installation operations. They do not authorize uploading audio/text. Optional remote providers still need separate transfer approval, scoped credentials and revocation in ticket 47. Voice Profiles and semantic search stay local. Never pass acoustic embeddings/profile storage into LLM context, text embeddings, exports, diagnostics or CLI output. None of these probes tests the future app's storage isolation by itself.

## Remaining evaluation lanes

Before claiming the associated product requirements pass, dependent tickets must supply:

- Consented representative Ukrainian/English human and code-switched speech, silence/no-speech, overlaps, echo and noisy/device-varied recordings, with labelled timing and identity ground truth. Evaluate errors and uncertainty rather than copying advertised thresholds.
- Long recordings processed in full with bounded memory/work, checkpoint recovery, per-track failure behavior, and timing continuity while the next Capture Session starts and previous work finalizes. These short-fixture probes do not prove that lane.
- Grounded English summaries/outcomes with valid citations, ambiguous ownership, rejected proposals and quoted hostile instructions across representative Meetings; schema success alone is insufficient.
- Product search archive defaults, edit/reprocess/purge/delete refresh, private-profile exclusion, full-text chunk coverage and source navigation. The standalone vector ranking experiment is not their implementation.
- Native UI tests for later UI tickets, and the 95% new/changed Swift gate for every shipped adapter. Ticket 03 adds no UI, migrations, operational store or production Swift, so native UX acceptance and schema/restart migration are not affected here.

Unsupported quality or runtime behavior must produce a visible constraint/setup failure and retain evidence. These results authorize neither broader audio capture nor remote upload nor weaker content-preservation requirements.

## Ticket disposition and validation

Ticket 03 is resolved **as a capability investigation**, with failed quality results preserved. It does not certify that R7/R9/R12 are implemented or all model quality requirements are supported. Fully local transport/inference is demonstrated; the evaluated tiny analysis model is unsuitable, whole-clip mixed-language ASR fails, and human diarization/recognition quality remains unverified. No shipping analysis model or voice threshold is approved by this investigation. Dependent tickets may use this contract to implement/evaluate candidates, but may not claim the missing capability passes.

[Validation evidence](capability-validation-2026-11-01.json): 53 behavioral probe tests passed, zero skipped/failures. Actual missing-loopback Pi acknowledged then settled with provider error and no artifact. Fresh ASR inference, downloaded speaker/text embedding inference and four actual Pi/LLM fixtures are separately attached above; unit-test success does not turn failed quality fixtures into passes. Exact retained held-out voice bytes were checked against the measured report without re-running inference after the retention-only change.
